# V2: manually configured bearer tokens

HTTP MCP requires a token for **every** `/mcp` request, including initialization,
notifications and tool calls. Missing/wrong/malformed/duplicate credentials get
`401 Unauthorized` with `WWW-Authenticate: Bearer realm="markdown-brain"`, before
MCP processing. There is no unauthenticated HTTP mode or old-flag fallback.

Each registered token has a unique client name and the same allowed-root policy:
read/search and edit existing supported Markdown anywhere; create new notes only
inside lowercase root-relative `ai/`, including existing subdirectories. Parent
directories must already exist. All clients can also use `attachment_create` to
upload PNG/JPEG/GIF/WebP images only under lowercase root-relative
`ai/attachments/`, with existing parents, max 1 MiB, matching signature/extension
and no overwriting. See [image limits](../README.md#image-attachments). These
creation-only boundaries also apply to stdio; no auth/config change is needed. Authenticated MCP request logs include that name, not the token. This is
basic request attribution, not a complete per-tool audit trail. No users,
database, OAuth/login UI, expiry, scopes, or admin HTTP endpoints are introduced.

## 1. Generate a client token

On your own trusted machine:

```sh
openssl rand -hex 32
```

Copy the resulting 256-bit random token into that MCP client's secret store or
private configuration. Generate a different token for each client. Do not reuse
a password. Supported token text is 32–256 URL-safe characters (letters,
numbers, `_`, `-`); the command above produces 64 lowercase hex characters.

The application never generates or installs real credentials automatically.
Only throwaway test credentials are generated by the tests. Do not paste tokens
into chat, commit them, pass them as command-line arguments, or put them in URLs.

## 2. Calculate its SHA-256 hash

After `pnpm build`, use this Bash snippet to read the copied token without putting
it in shell history, process arguments, exported environment variables, or echoing
it to the terminal:

```sh
unset TOKEN
read -rsp 'Paste client token: ' TOKEN; printf '\n'
printf '%s' "$TOKEN" | node dist/src/token-hash.js
unset TOKEN
```

Only the hash is printed. Alternatively pipe token input to `pnpm --silent auth:hash`
when development dependencies are available. The helper reads stdin only; an
optional final newline is ignored. Its error messages never echo invalid input.

## 3. Edit the application configuration

For the local Compose setup:

```sh
mkdir -p .local/config
chmod 700 .local/config
cp config/auth.example.json .local/config/auth.json
chmod 600 .local/config/auth.json
```

Replace the intentionally invalid placeholder in `.local/config/auth.json` with
the hash from step 2, and choose a name. The format is:

```json
{
  "version": 1,
  "tokens": [
    { "name": "claude-desktop", "sha256": "REPLACE_WITH_64_LOWERCASE_HEX_SHA256_HASH" },
    { "name": "coding-agent", "sha256": "REPLACE_WITH_ANOTHER_UNIQUE_HASH" }
  ]
}
```

Names must be 1–64 ASCII letters/numbers/underscores/hyphens, starting with a
letter or number. Hashes must be unique lowercase 64-character hex values;
names must be unique too. Config supports 1–128 entries, maximum 64 KiB, and
rejects unknown fields. A raw `token` field is deliberately invalid. Config
errors do not echo its contents.

This is a **manual admin-managed file**, not part of the Markdown collection or
QMD cache. Restrict who can modify it: anyone able to add an entry can grant
access. It contains hashes, not usable bearer credentials, but should still be
private and excluded from version control. `.local/` is ignored by Git and the
Docker build context. Back it up independently of disposable search state.

Compose mounts the whole config directory read-only at `/config` (so replacing
the file atomically on the host works). The container runs as UID/GID 1000 and
must be able to read the directory/file; arrange ownership appropriately. On
SELinux-enforcing hosts, give this dedicated directory an appropriate container
label, e.g. Compose `bind.selinux: Z`. Do not loosen permissions on unrelated
paths. `AUTH_CONFIG=/config/auth.json` is the container default; a direct Node
HTTP process must set `AUTH_CONFIG` explicitly. The final file must be a regular
file, not a symlink. Missing/empty/invalid config prevents HTTP startup.

## 4. Start/restart and configure clients

```sh
docker compose up --build -d
```

Client requests must contain:

```http
Authorization: Bearer <the-original-token-not-its-hash>
```

For example, with the TypeScript MCP SDK, obtain `token` from your client's
secret source (not a committed string):

```ts
const transport = new StreamableHTTPClientTransport(
  new URL('https://brain.rpi.example.com/mcp'),
  { requestInit: { headers: { Authorization: `Bearer ${token}` } } },
);
```

Exact secret/environment configuration depends on the MCP client. Clients must
support custom Authorization headers; static bearer tokens are **not** an OAuth
provider or an interactive MCP authorization/discovery flow.

**Require HTTPS for remote clients**, terminated by Traefik. Plain HTTP is only
appropriate on loopback for these local Docker tests, or the private
proxy-to-container hop. A stolen token grants all of these note permissions until revoked.
Do not publish the container's application port directly in a remote deployment.
Do not log Authorization headers in proxy/access/debug logs. Host/Origin checks
remain enabled, but are not authentication or a replacement for TLS.

## Add, rotate, revoke

- **Add:** generate a fresh token, add a named hash, restart, configure the client.
- **Rotate:** add a new named hash, restart, update the client, remove the old hash,
  restart again. Both tokens work during the overlap.
- **Revoke:** remove the entry, then `docker compose restart brain`.
- **Revoke all:** stop the service. An empty token list intentionally prevents startup.

Configuration is read **once at process startup**. Editing the file alone does
not revoke a token or authorize a new one. Restart is mandatory. Already
accepted requests may finish during graceful shutdown; there are no long-lived
MCP sessions to revoke separately.

`GET /health` remains unauthenticated liveness with no note/index information,
subject to Host/Origin validation. Other paths remain 404. Stdio is unchanged:
the local OS process/user boundary controls it, not HTTP tokens.

## Verification

`pnpm test` checks config rejection, hashing, credential rejection, real HTTP
MCP calls with two independently named clients, and write safety. After
`docker compose build`, `pnpm test:docker` mounts a temporary hash-only config
read-only, verifies unauthenticated access is denied, exercises real QMD/file
operations, removes a token from the config, restarts, proves revocation, and
rebuilds disposable indexes without losing Markdown. All test containers and
volumes are removed. No real credential, vault, or Pi deployment is involved.
